ALV 리포트를 OData V4 API로 노출하기: Custom Entity + SUBMIT

기존 ALV 리포트를 건드리지 않고, SUBMIT 으로 최종 출력 데이터를 가로채 RAP Custom Entity 로 실시간 OData V4 API 를 만든 과정과 소스 전체

개요

  • 기존 ALV(cl_gui_alv_grid) 리포트의 최종 출력 데이터를 OData V4 Web API 로 노출하는 시나리오
  • 리포트는 수정하지 않고 SUBMIT + cl_salv_bs_runtime_info 로 ALV 화면 없이 데이터만 가로채 Custom Entity 로 응답. Z 테이블 없이 호출 시점마다 실시간 조회
  • 개발 순서: 선택화면 이름 확인 → Custom Entity → Query Provider 클래스 → Service Definition/Binding → 호출 테스트
  • 리포트 본체(START-OF-SELECTION, ALV 호출부)는 이 문서에서 생략하고 TOP include 기준으로 정리
  1. 호출자Postman, 외부 시스템 (GET)
  2. Service BindingOData V4 - Web API
  3. Query ProviderIF_RAP_QUERY_PROVIDER~SELECT
  4. SUBMIT 낚아채기ALV 화면 없이 데이터만 수신
  5. 응답JSON (필터, 정렬, 페이징 적용)

1

기존 리포트 선택화면 (TOP include)

  • SUBMIT ... WITH 이름 IN range 의 이름은 리포트의 SELECT-OPTIONS 이름과 글자 하나까지 같아야 함
  • 이름이 달라도 에러 없이 조용히 무시되어 조건이 안 걸림 (막혔던 지점 참고)
  • 아래 소스는 오타를 고친 최종본. s_carid → s_carrid
  • 화면용 코드(popup, ok_code 등)는 SUBMIT 방식 API 호출에서는 사용되지 않음
2

Custom Entity 생성

  • @ObjectModel.query.implementedBy: 'ABAP:클래스명' 이 데이터를 만들어 주는 클래스를 지정
  • 호출이 들어올 때마다 해당 클래스의 IF_RAP_QUERY_PROVIDER~SELECT 가 실행됨
  • key 는 carrid, connid, fldate. 금액 필드는 @Semantics.amount.currencyCode 로 통화 필드(CURRENCY)를 연결
  • element 이름이 소문자/대문자 혼용. OData 호출 시 정의한 이름 그대로 사용
3

Query Provider 클래스

  • SELECT 흐름: 필터 → range 변환 → get_alv_data (SUBMIT) → 정렬 → $count → 페이징($top, $skip)
  • get_alv_data: cl_salv_bs_runtime_info=>set (display 끄고 data 켬) → SUBMIT → get_data_ref → clear_all 필수
  • 필터 이름 <f>-name 은 대문자(CARRID, FLDATE)로 도착
  • get_data (SFLIGHT 직접 조회)는 대안으로 남겨두었고 현재 호출부는 주석 처리, get_alv_data 사용
4

Service Definition / Service Binding

  • Custom Entity 를 Flights 라는 이름으로 expose. 호출 URL 의 엔티티셋 이름이 됨
  • Service Binding 은 OData V4 - Web API 로 생성하고 Activate. 이 단계는 소스 없이 ADT 에서 생성

호출 테스트

  • URL 은 Service Binding 화면의 Service URL 을 기준으로 하고 뒤에 /Flights 를 붙임. 아래 <바인딩명> 은 자리표시
  • 필드명은 Custom Entity 에 정의한 이름 그대로. 소문자 carrid, fldate (대문자 CARRID 로 쓰면 못 찾음)
  • 문자열은 작은따옴표, 날짜는 따옴표 없이 2026-10-27 형식. 조건은 and 로 연결, 옵션 사이는 & 로 연결
  • 필터 없이 호출하면 리포트 전체가 실행됨. 조건을 꼭 포함해서 호출

막혔던 지점 정리

  • SUBMIT 으로 넘긴 조건이 리포트에 전달되지 않았던 문제. 원인은 선택화면 변수 이름 오타
증상원인해결
항공사 조건이 SUBMIT 에 전달되지 않음. 에러 없이 조회됨호출 쪽은 with s_carrid in ir_carrid (r 두 개), 리포트 선언은 s_carid (r 한 개). 이름이 맞지 않는 WITH ... IN 은 에러 없이 무시됨리포트 선택화면을 s_carrid 로 수정해 호출 쪽 이름과 일치시킴. 값이 의심되면 리포트 START-OF-SELECTION 에서 s_carrid[] 를 확인

운영 전 보완 메모

  • 동작은 확인되었고, 운영 반영 전에 아래 항목을 점검
  • SUBMIT 방식은 ABAP Cloud(Tier 1)에서 사용할 수 없으므로 장기적으로는 조회 로직을 클래스로 분리하는 방향(get_data)이 목적지
항목이유조치
빈 CATCH 블록 (cx_rap_query_filter_no_range, cx_salv_bs_sc_runtime_info)에러가 나도 빈 결과로 보임. 서로 다른 필드를 섞은 복잡한 or 조합은 range 하나로 표현되지 않음예외를 다시 던지거나 로그를 남김
필수 조건 / 상한 건수매 호출마다 리포트가 전체 실행됨. $top 을 줘도 비용은 동일필수 필터 검사와 최대 건수 제한 추가
TOP include 하단 select from scarr ... @data(gt_data)include 로드 시 실행되어 SUBMIT 때마다 같이 실행됨쓰지 않으면 삭제, 쓰면 START-OF-SELECTION 으로 이동
