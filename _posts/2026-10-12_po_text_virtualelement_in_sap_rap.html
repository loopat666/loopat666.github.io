PO 품목 롱텍스트를 CDS로 노출하기 — RAP Virtual Element

EKPO 기반 CDS에 구매오더 품목 텍스트(EKPO/F01)를 붙여 OData V4로 노출했다. 텍스트는 DB에서 직접 읽을 수 없어 Virtual Element 계산 클래스에서 READ_TEXT로 채운다.

개요

  • EKPO 데이터를 CDS로 노출하면서 품목 롱텍스트(TDOBJECT EKPO, TDID F01)를 함께 내보내는 시나리오
  • 롱텍스트는 STXL에 인코딩되어 CDS로 못 읽음 → Projection View에 virtual 필드 선언 + SADL 계산 클래스에서 채움
  • 개발 순서: 저장 구조 확인 → Interface/Projection View → 계산 클래스 → OData로 테스트
  1. 호출자Ariba CIG / Fiori Preview / GW Client
  2. OData V4 서비스ZC_2227_POTEXT01 노출
  3. SADL 조회DB SELECT · 필터 · 페이징(200건)
  4. 계산 클래스STXH 선별 후 READ_TEXT
  5. 응답ItemLongText 포함 JSON

텍스트 저장 구조 조사

  • PO 품목 텍스트 원본은 STXH(헤더) + STXL(본문)
  • STXL 본문은 LRAW로 인코딩되어 있어 CDS·SE16N으로 읽을 수 없음 → READ_TEXT로 디코딩해야 함
  • TDNAME = EBELN(10) + EBELP(5) 15자리 (예: 450000012300010)
후보확인 결과판단
STXH / STXLPO 텍스트 존재. STXL은 인코딩 상태원본. READ_TEXT로 접근
ESH_SR_LTXT자재·생산오더 텍스트만 있고 PO 없음Enterprise Search용. 사용 안 함

2

CDS View · 서비스

  • Virtual Element는 Projection View에 선언. 계산 클래스는 @ObjectModel.virtualElementCalculatedBy: 'ABAP:클래스명'으로 연결
  • 클래스명은 실제 클래스와 정확히 일치해야 함. 수정 후 뷰 재활성화
  • CDS를 먼저 활성화해야 계산 클래스도 활성화됨 (클래스가 뷰를 타입으로 사용)
3

계산 클래스

  • get_calculation_info: 계산에 필요한 원본 element를 SADL에 요청. 뷰 element 이름을 대문자로 (EBELN, EBELP)
  • calculate: STXH로 텍스트 있는 품목만 1회 선별 → 해당 품목만 READ_TEXT 호출. 없거나 실패하면 스킵(빈 문자열)
  • 내부 테이블 타입은 Virtual Element가 선언된 Projection View(zc_2227_potext01). Interface View로 선언하면 ItemLongText 필드가 없어 에러
  • 줄 구분자는 공백. 공백은 백틱(` `)으로. 작은따옴표 ' '는 뒤 공백이 잘림

호출 테스트 · 디버깅

  • ADT Data Preview(F8)에서는 Virtual Element가 항상 비어 있음 — DB 직접 조회라 SADL을 안 거침
  • Service Binding Preview 또는 /IWFND/GW_CLIENT로 OData 호출해서 확인
  • 디버깅은 ADT external breakpoint (Preferences > ABAP Development > Debug의 user가 호출 사용자인지 확인)
  • Virtual Element는 요청된 경우에만 계산됨 ($select 또는 화면 컬럼에 포함)

성능 · 페이징

  • calculate는 필터·정렬·페이징이 끝난 뒤 응답 행에 대해서만 호출 → 부하는 페이지 크기에 비례
  • $top이 없어도 서버 측 페이징으로 200건씩 응답, 응답 끝에 @odata.nextLink
  • 호출자(CIG)가 nextLink를 끝까지 따라가는지 확인 필요 — 안 따라가면 200건 이후 누락
  • READ_TEXT는 텍스트 있는 품목마다 1회(STXL 읽기 + 디코딩)

실무 활용 케이스

  • 판단 기준: CDS로 못 만들고, 필터·정렬이 필요 없는 읽기 전용 값
