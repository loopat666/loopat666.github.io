개요

  • 한 번의 호출로 항공사(헤더)와 항공편(아이템)을 함께 받는 static action ImportData를 unmanaged RAP로 만든다.
  • 행마다 따로 검증해서 통과한 행만 저장하고, 실패한 행은 사유와 함께 응답한다 (부분 성공).
  • 개발 순서는 테이블 → 입력/리턴 AE → abstract BDEF → BDEF → 로직 클래스 → BP 클래스 → 호출 테스트.
  1. 호출자POST + JSON body
  2. 서비스OData V4 static action
  3. 검증recv_data, 행별 판정
  4. 저장save, 항공사 → 항공편
  5. 결과요약 1줄 + 행별 S/E

1

테이블

  • 항공사 yhl2609t0030은 mandt + carrid, 항공편 yhl2609t0031은 mandt + carrid + connid가 키.
  • 항공사 테이블에서 key carrid를 빠뜨리면 키가 mandt 하나뿐이라 클라이언트당 1건만 저장된다.
  • distance는 distid와 수량-단위 짝이라 @Semantics.quantity.unitOfMeasure로 묶는다.
2

수신 구조 (입력 AE)

  • root AE 아래에 HEADER(송장 정보), DATA(항공사 N건), ITEMS(항공편 N건)가 형제로 달린다.
  • DATA와 ITEMS를 이어주는 건 carrid 값뿐이라, 부모 존재 여부는 로직 클래스에서 직접 검증한다.
  • currcode(통화키), distid(단위) 같은 형식 타입은 존재하지 않는 값이 오면 로직에 닿기 전에 HTTP 400이 난다.
3

리턴 구조 (리턴 AE)

  • root 1건 아래 RETURN 메시지가 N건 달리는 구조. 건마다 carrid, mtype(S/E/W), message를 내려준다.
  • 필드 이름이 그대로 JSON 키가 되므로 messgae 오타는 서비스 공개 전에 message로 고쳤다.
4

Abstract BDEF

  • action 파라미터/결과로 쓰는 AE는 root마다 abstract BDEF가 있어야 한다.
  • abstract; strict ( 2 ); with hierarchy; 헤더 아래에 엔티티별로 빈 define behavior만 둔다.
5

BDEF (unmanaged)

  • deep parameter로 입력 트리를, deep result로 리턴 트리를 주고받는 static action. 응답은 value 배열 안에 root 1건으로 내려온다.
  • 항공편을 따로 생성하지 않으므로 association _Schedule;만 선언하고 create는 쓰지 않는다. BP에도 cba_Schedule을 두지 않는다.
  • authorization master ( global )을 쓰므로 BP에 get_global_authorizations 메서드가 있어야 한다.
6

로직 클래스

  • recv_data: 빈 요청 확인 → 항공사 검증 → 항공편 검증(부모 판정 포함) → 통과행만 버퍼 적재 → 행별 로그 → 리턴 조립 → 맨 앞에 요약 1줄.
  • 검증 규칙 하나 = 메서드 하나. 새 규칙은 validate_airline / validate_schedule에 한 줄만 추가한다.
  • save는 부모(항공사) → 자식(항공편) 순으로 insert하고 로그는 항상 저장한다. COMMIT WORK는 쓰지 않는다.
상황처리
요청 안에서 같은 키가 2번 이상둘 다 에러 (어느 쪽이 맞는지 알 수 없음)
이미 DB에 있는 항공사 / 항공편에러 (이미 수신됨)
같은 LUW의 앞선 호출에서 이미 접수된 키이번 행만 에러 (먼저 온 쪽이 우선)
같이 보낸 항공사가 실패그 항공사의 항공편도 함께 에러
항공사 없이 항공편만 전송DB 또는 같은 LUW에 항공사가 있으면 접수, 없으면 에러
7

BP 클래스

  • lcl_buffer가 로직 클래스 인스턴스를 들고 있다가, save에서 한 번에 저장하고 cleanup에서 인스턴스째 버린다.
  • ImportData 핸들러는 얇게 recv_data에 위임한다. 건별 판정과 리턴 메시지는 action 안에서 확정하고, save는 확정된 데이터를 쓰기만 한다.
  • read, rba_Parent는 빈 껍데기라 조회는 되지 않는 쓰기 전용 API.
8

호출 테스트

  • CSRF 토큰을 GET으로 먼저 받은 뒤 POST. body 키는 $metadata의 이름과 대소문자까지 같아야 한다.
  • 날짜는 2026-11-02, 시간은 22:50:00 형식, connid는 4자리 문자열(0001)로 보낸다.
  • payload는 성공 3건과 에러 케이스를 섞어서 검증 규칙이 하나씩 울리도록 만들었다.
