바이브 코딩 작업 시작 절차와 난이도 레벨

다음 프로그램, 테이블, CDS view를 만들 때 무엇부터 시작하고 어디까지 Claude Code에 맡길지 정리했다. 형이 설계하고 검수하고, Claude Code가 조사하고 구현한다.

개요

  • 시작은 항상 요구사항 카드 → 레벨 판정이다. 레벨이 절차의 무게를 정한다.
  • 직접 짜면 30분 안에 끝나는 일은 Claude Code를 쓰지 않는다. 조사가 필요한 일과 반복 작업에 쓴다.
  • 서버 쓰기는 백업 → diff 승인 → 활성화 → 형이 직접 테스트 순서를 지킨다.
  1. 1. 카드 작성목표/입출력/제약/완료 조건
  2. 2. 레벨 판정L0 / L1 / L2 / L3
  3. 3. 계획 승인L2 이상, 계획 1회
  4. 4. diff 승인백업 후 쓰기, 구문 체크
  5. 5. 테스트와 이력직접 실행, 이력 1회
레벨한 줄 정의계획서이력
L0 스니펫오브젝트 0개, 서버 쓰기 없음없음없음
L1 소형오브젝트 1~2개, 직접 30분 이내생략생략 또는 한 줄
L2 중형오브젝트 3~6개, 조사/시행착오 필요1회마지막 1회
L3 대형오브젝트 7개 이상, 되돌리기 어려움단계별단계별 또는 묶음
1

요구사항 카드 (시작 전 5분)

  • 이게 없으면 Claude Code가 추측하고, 추측이 쌓이면 시간이 늘어난다.
  • 한 단락이면 충분하다. 완료 조건을 구체적으로 쓰는 게 핵심이다.
  • 시작 전에 searchObject로 비슷한 오브젝트가 이미 있는지 확인시킨다.
2

난이도 레벨 L0~L3

  • 레벨은 오브젝트 수, 조사 필요 여부, 되돌리기 난이도로 정한다. 애매하면 한 단계 높게 잡는다.
  • 작업 중 커지면 레벨을 올리고 그 시점에 계획서를 받는다.
레벨예시절차형의 역할시간 감
L0 스니펫정규식 한 줄, SQL 한 문장, 문법 확인한 번 묻고 끝복붙해서 확인~5분
L1 소형payload JSON 생성, 간단 리포트, 필드 1~2개 추가계획 생략, diff만 보고 승인diff 검수~30분
L2 중형기능 추가(오늘 composition), CDS 뷰 설계, 테이블+CDS 세트계획 1회 → 승인 → diff 승인 → 테스트 → 이력 1회설계 결정, 검수, 테스트1~2시간
L3 대형수신 API 신규(AE+BDEF+BIMPL+로직 클래스+SD/SB), Event Mesh 실습단계로 쪼개고 단계마다 승인과 테스트설계 전체, 단계마다 활성화/테스트반나절 이상

Claude Code를 쓸지 말지

상황판단
직접 짜면 30분 안에 끝남쓰지 않는다 (설명하는 시간이 더 걸린다)
표준 클래스나 API를 찾아야 함쓴다 (조사가 강점. 오늘 CL_SBD_STRUCTURE_PERSIST 사례)
payload 대량 생성, 반복 보일러플레이트쓴다 (반복 작업)
설계 결정 자체 (키, 필드, 구조)형이 결정한다. Claude Code는 초안만
3

공통 안전 장치 (모든 레벨)

  • 서버 쓰기 전에 백업하고, diff만 보고 승인한다. 승인한 diff와 달라지면 다시 승인받는다.
  • 구문 체크 오류는 보고만 하고 수정은 승인 후에. 마지막 활성화와 테스트는 형이 직접 한다.
  • 권한 프롬프트는 읽고 1번만 누른다. auto mode와 "don't ask again"은 쓰지 않는다.
항목규칙
거절할 도구deleteObject, forceUnlock, transport*, runSnippet
백업쓰기 전에 활성 소스를 docs/backup/<이름>.before.abap으로 저장
추측 금지필드명은 AE/CDS 소스 기준. 실제 존재 확인된 이름만. 불확실하면 "검증 필요"로 표시
LUWCOMMIT WORK 직접 호출 금지, DB 쓰기는 saver
접속 정보비밀번호와 토큰은 프롬프트, 코드, 커밋에 넣지 않음 (환경변수 사용)
중단Esc 한 번. Ctrl+C 두 번은 종료다. 복사는 드래그(copyOnSelection)나 Ctrl+O
비released API연습용으로만. 운영 코드에는 쓰지 않는다
4

오브젝트별 시작 방법

  • 테이블과 CDS는 설계는 형, 초안은 Claude Code. 키와 구조는 형이 먼저 정한다.
  • CDS는 IV → PV → (필요 시) MDE/AC 순서. SD는 PV를 expose한다.
  • L3는 단계로 쪼개고, 단계마다 활성화하고 테스트한 뒤 다음으로 넘어간다.
오브젝트레벨시작 방법
테이블 (DDIC)L1~L2키/필드/데이터 엘리먼트/통화 참조는 형이 결정. 기존 비슷한 테이블을 읽혀 define table 초안과 네이밍 점검
CDS viewL2@소스를 지정하고 필드명은 소스 기준으로만 작성. 변환 Exit 필드는 IV에 raw, PV에서 변환
프로그램/리포트L1~L2로직은 클래스, 프로그램은 호출과 표시만(얇게)
RAP 수신 API 신규L3아래 6단계로 쪼갠다

프롬프트 틀

  • 목표, 맥락, 제약, 완료 조건을 한 번에 준다. 읽을 파일은 @로 명시한다.
  • 한 번에 크게 시키지 말고 분석 → 계획 → 구현 → 검증 순서로 쪼갠다.
  • 막히면 에러 메시지 전문과 직전에 한 작업을 같이 준다.
6

CLAUDE.md에 붙일 블록

  • 프로젝트 루트의 CLAUDE.md 맨 아래에 붙이면 매번 설명하지 않아도 된다.
  • 기존에 있는 규칙(추측 금지, 단계별 승인, COMMIT 금지)과 겹치는 줄은 정리해서 넣는다.
  • 접속 정보가 든 설정 파일(.mcp.json 등)은 읽거나 출력하지 않는 규칙도 같이 둔다.
7

막혔던 지점 정리 (11/13~11/15 실습)

증상원인해결
Claude Code가 갑자기 종료됨Ctrl+C 두 번중단은 Esc 한 번. 복사는 드래그(terminal.integrated.copyOnSelection)나 Ctrl+O. 재개는 claude --continue (검증 필요)
승인 없이 소스가 바뀜Claude Code가 구문 경고를 스스로 수정CLAUDE.md에 "달라지는 수정은 다시 승인" 규칙 추가
프로그램이 비활성으로 남음생성 후 활성화 누락setObjectSource(activate=true)로 한 번에 처리
setTextElements 락 에러 (423)텍스트 요소 리소스 락선택 텍스트는 SE38에서 수동 입력
Field "VALUE" is unknownVALUE STANDARD TABLE OF ... WITH EMPTY KEY( ... ) 사용이름 있는 테이블 타입 선언 후 VALUE tt_xxx( ... )
EMPTY KEY 테이블 SORT 경고SORT itab.SORT itab BY table_line.
RETURNING과 EXPORTING 동시 선언RETURNING 메서드는 IMPORTING만 허용 (구문 오류 가능)반환값도 EXPORTING으로 통일하고 호출부를 맞춤
CDS 이름 칸에 프로그램 이름 입력이름이 비슷해 혼동"CDS entity ... not found (active)." 입력 검증 메시지로 정상 종료됨
MCP로 데이터 미리보기 불가정책으로 막혀 있음ADT SQL 콘솔이나 SE16N으로 형이 직접 확인하고 결과를 전달
계획서에 중복/과거 정보긴 대화 이력 누적요약을 주고 계획서를 다시 쓰게 하거나 새 세션에서 시작
